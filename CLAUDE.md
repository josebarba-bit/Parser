## Project Overview

Web-based QA Test Dashboard hosted on **GitHub Pages** (`josebarba-bit/Parser`).
Aggregates Robot Framework and Python test results across multiple PCs and test types,
displaying them in a single `index.html` dashboard with tabs per test category.

**Owner:** Jose Barba — QA Automation Engineer, Oregan Networks  
**Clients:** Telus, Mega/Tizen  
**STB Models:** UIW, VIP

---

## Tech Stack

- **Frontend:** Vanilla HTML + CSS + JavaScript (single `index.html`, no build step)
- **Data pipeline:** Python publisher scripts → CSV files → parsed by `index.html` at runtime
- **CI/CD:** Jenkins (Windows, freestyle jobs) → triggers publishers post-build
- **Source control:** Bitbucket (internal) mirrored to GitHub Pages for dashboard hosting
- **Test framework:** Robot Framework (`.robot` files) + Python scripts for Stability/Memory

## Coding Standards and Conventions

### JavaScript (index.html)
- All logic lives inside `index.html` — do **not** split into separate `.js` files unless explicitly asked
- Use `fetch()` for loading CSVs at runtime — no bundlers, no npm
- Tab switching via CSS class toggling — keep it simple, no frameworks
- PDF export uses `jsPDF` loaded from CDN
- Comments in **English only**

### Python (publishers)
- Python 3.x, standard library preferred
- Comments in **English only**
- `run_daily()` function must remain **commented out** in `stability_publisher.py` — only uncomment temporarily for testing
- Use `xcopy /Y` for file copying (Windows compatibility, not `cp` or `shutil` for deployment)
- Use `ping -n 2 127.0.0.1 > nul` for delays instead of `timeout` (Jenkins Windows compatibility)
- Each publisher is standalone — do not create shared imports between them

### CSV Format
- CSVs are auto-generated by publishers — treat them as **read-only artifacts**
- Do not manually edit or reformat CSV files
- Delimiter: comma (`,`), encoding: UTF-8

### Key Metrics in Dashboard
- **Baseline:** Reference value for a given metric under normal conditions
- **Drift %:** Percentage deviation from baseline
- **OOB (Out-of-Baseline):** Count of samples exceeding the acceptable threshold
- **OOB Rate:** Percentage of total samples that are out-of-baseline

## Security and Restricted Access

- **Do not** hardcode Bitbucket or GitHub credentials in any script
- Git remote URL must **not** contain embedded username/password (causes 403 on push)
  - Correct: `https://github.com/josebarba-bit/Parser.git`
  - Wrong: `https://user:token@github.com/...`
- API keys or tokens must be stored in a separate `.env` file (not committed)
- `.env` must be listed in `.gitignore`

## AI Code Generation Guardrails

When generating or modifying code in this project:

1. **Do not refactor working publisher scripts** unless explicitly asked — stability matters more than elegance
2. **Do not add npm/node dependencies** — this is a no-build-step project
3. **Do not split `index.html`** into components or modules unless asked
4. **Do not change CSV column names** — the dashboard parser depends on exact header names
5. **Preserve the `run_daily()` comment** in `stability_publisher.py` — never uncomment it in a commit
6. **Match the existing code style** — no type hints unless already present, no f-strings if the file uses `.format()`
7. **Test changes locally** before suggesting a git push
8. **Ask before changing** anything related to Jenkins job configuration or post-build scripts
